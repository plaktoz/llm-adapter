## Defaults taken

The owner can veto any of these before B1 starts.

| Default | Why |
|---------|-----|
| The Responses adapter lives in `adapters/responses.py`. The empty stubs `adapters/openai.py`, `adapters/gemini.py` and `adapters/openai_compat.py` are deleted, and `tests/test_import.py` is updated to match | ADR 0001: one Responses adapter serves OpenAI and Gemini. `openai_compat` is v2 (D19), and an empty v2 file is noise |
| The adapter interface (`complete(request, model, timeout) -> Response` and `classify(exc) -> ErrorClass`) is a `typing.Protocol` in `types.py` | The core and the adapters can then be built in parallel against one contract |
| Each adapter keeps one SDK client per thread with `threading.local` | D30 |
| `ContextOverflow.model_limit` is the alias's `context_window` (D33), so it is set from config, not from the provider body | The provider body may not state the limit (F3) |
| Waits go through an injectable `sleep` function, so tests use a fake clock | AT-1 and AT-11 must not sleep for real |

## Pre-check

Added at the owner's request on 2026-11-09. Decision D34 and the proposed values D35 are in `docs/requirements.md`.

- Implemented in `src/llm_adapter/precheck.py`: `estimate_prompt_tokens` (characters of `system` and of every message, divided by 4, rounded up) and `check_prompt_size`. It raises `ContextOverflow` with `model_limit` set to the alias's `context_window`. The message holds counts only, never prompt text.
- `complete` does not exist yet (`core.py` is a stub until B4), so nothing calls the check yet. B4 must call it before the first provider call. This is recorded in B4's "Done when" and in AT-14.
- Error raised: section 4 already says `ContextOverflow`, no retry, no failover (D13). The task followed that. No new behaviour was invented.
- Tested now: `tests/test_precheck.py` (estimate, boundary at the window, over the window, limit carried, no prompt text in the message). Not tested yet: that `complete` makes no provider call and fires no `on_usage` event. That is AT-14, in B4 and B7.
- `context_window` values: 272000 for `default` and `deep`, 1000000 for `planner`. The owner chose 272000 on 2026-11-09. It is the smallest GPT `max_input_tokens` the gateway reports, so it holds for any GPT fallback (D35). `planner` has no fallback, so it keeps the primary's 1000000.
- Not decided: a safety margin on the estimate. Characters divided by 4 is a rough rule for English text. It can undercount for code, other languages and some tokenizers.

## Known limits of the build

- The context-overflow bodies in AT-8 and AT-10 are written by the test, not captured from a real server (F3). The tests prove the classifier against that shape only.
- AT-12 shows that calls are independent. It cannot prove that the SDKs are thread-safe. D30 avoids depending on that.
- The worst-case times of section 5 are arithmetic. AT-1 checks the waits with a fake clock, not real time.
